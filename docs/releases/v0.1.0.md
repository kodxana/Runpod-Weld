# Runpod Weld 0.1.0 — first Linux release

Linux amd64 only. This release builds trusted Dockerfiles into OCI images inside
ordinary Linux Pods without a Docker daemon. It is an early release, not full
Docker/BuildKit compatibility or a security sandbox.

## Install

Download `rpweld_0.1.0_amd64.deb` and verify it against `SHA256SUMS`, then:

```sh
sudo dpkg -i rpweld_0.1.0_amd64.deb
rpweld --version
rpweld doctor
```

The package includes Weld, Skopeo, its ELF shared-library closure, its loader and
CA certificates. Installation needs no downloads, Skopeo package, Docker, Rust,
or system-library upgrade. The backend lives under `/usr/lib/rpweld`, without
replacing `/usr/bin/skopeo`, `/etc/containers/policy.json` or system certificates.
There are no install/remove scripts. Removing the package keeps user build data.
Debian 12 is the offline installer validation target.

For a portable installation, extract `rpweld-0.1.0-linux-amd64.tar.gz` and run
`./rpweld-0.1.0-linux-amd64/bin/rpweld`. Keep `bin`, `lib`, and `share` together.
The Weld executable is statically linked; moving it alone loses the bundled
registry backend (local OCI builds still work). The backend uses its own loader
and libraries, so it does not require the host's glibc version to match.

Existing system signature policy always wins, including rejection or malformed
policies. Only an absent system policy uses the bundled default, which accepts
unsigned images while still enforcing HTTPS certificate verification. Existing
system CA roots and explicit CA settings are preserved. The bundled CA snapshot
is a fallback on systems without CA roots. Reinstall a newer release to update
bundled libraries/certificates; the host package manager does not patch them.
Optional external credential helpers and GnuPG signing-policy integrations still
require the operator's own tools/keyrings. Missing signing tools fail closed.
Signed tag/index identity changes remain explicitly unsupported.

If an older manually installed `/usr/local/bin/rpweld` shadows `/usr/bin/rpweld`,
`command -v rpweld` reveals it. Invoke `/usr/bin/rpweld` explicitly or relocate
the old binary yourself; the installer never deletes it.

## Included

- Layered output by default, with explicit flattened export available.
- Multi-stage builds, external-image COPY, USER, common metadata instructions,
  bounded RUN/COPY heredocs, multiple tags, registry login/push and progress.
- Automatic resource sizing, measured admission checks, bounded registry
  preflight, verified shared cache, explicit cache maintenance and recovery.
- Reduced replay/export work for layered builds, especially `--no-cache`:
  COPY-only stages avoid unneeded image exports; the last FROM consumer can
  reuse an owned parent filesystem. Integrity and ownership checks remain.
- The previously measured full Nemotron workload improved from 19m50s to
  16m40s on the same A40 Pod. That is a workload-specific observation, not a
  promised release-build speed or cached-build benchmark.

## Verification and source

`build-info.json` records the exact commit, toolchain, backend/package versions,
and hashes of installed payload files. `SHA256SUMS` covers release assets.
`rpweld-0.1.0-sources.tar.xz` includes the matching Weld sources, vendored Rust
dependencies and exact source packages for bundled distribution libraries.
License notices are included under `share/doc/rpweld/third-party`.
Weld is licensed under Apache-2.0; dependencies retain their own licenses.

The tag workflow tests before publishing; failed gates do not publish a release.
No ARM, macOS or Windows binaries are produced. RUN still needs the documented
Linux capabilities/native filesystem permissions; a self-contained package does
not bypass kernel restrictions or provide GPU access during builds.
