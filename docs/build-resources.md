# Managed build resources

`rpweld build -t NAME .` resolves finite automatic workload ceilings before creating build state or pulling bases. `--max-rootfs-bytes`, `--max-layer-bytes`, `--metadata-budget`, and `--max-entries` override their respective ceilings exactly. Smaller explicit ceilings are never enlarged. Explicit output/work builds without tags retain legacy defaults.

Disk sizing observes the actual work, output and store filesystems, including their nearest existing ancestors when paths do not yet exist. Shared-device estimates are added together. The policy rounds allowances down to powers of two based on filesystem capacity, so fluctuating free space does not change cache policy. It deducts a reserve of 5% of capacity, bounded to 256 MiB–4 GiB, and a 5% inode reserve bounded to 128–65536. Automatic bytes are capped at 1 TiB and entries at 16 million (further constrained by inode capacity and logical metadata). These are planning bounds: filesystem totals can be shared host capacity, quotas are unknown, and no space is reserved.

The stage estimate includes retained selected-stage roots/images, external images, spool/copy allowance, and separate work/output filesystems. Instruction checkpoints can retain substantially more space; this estimate is not peak usage. Additional measured writes and current resources must be checked at engine boundaries. Rechecks sum simultaneous additional allocations on the same filesystem, retain reserves, and refuse with operation, required and available quantities and the observation source. An arbitrary RUN or competing writer can still exhaust resources between observations.

Logical metadata charges count headers, paths, xattrs and bookkeeping; they are neither RSS nor disk bytes. A provisional automatic heuristic takes the observed cgroup operating ceiling, subtracts a memory reserve of max(128 MiB, 25%), divides by 16, rounds down to a power of two and caps the result at 4 GiB. The divisor allows room for simultaneous inventories and allocator overhead; it is not a calibrated RSS conversion or OOM guarantee. For example, a 50 GiB observed ceiling gives a 2 GiB logical allowance. Missing/ambiguous cgroups stay unknown and use a labelled finite 64 MiB logical fallback; large workloads may need an explicit metadata ceiling. Host RAM totals are never substituted. Current cgroup headroom is checked separately, including for explicit limits.

Large workload metadata never enlarges untrusted image JSON bounds (16 MiB/document, 64 MiB total), evaluated-plan bounds (16 MiB), descriptor count (1024), gzip header bound (64 KiB), or existing parser/depth limits. A smaller explicit metadata ceiling also constrains these subsystems. The existing replay code calculates exact pinned FD demand and may raise soft NOFILE only within the existing hard limit. Diagnostics describe unknown observations, auto/explicit origins and reserves even with `--progress quiet`.
